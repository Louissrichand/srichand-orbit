# Orbit

ระบบจัดการงานแบบ Asana สำหรับใช้เองในทีม — HTML/CSS/JavaScript ล้วน ไม่มี build step ไม่มี dependency

## ลองใช้

**เปิดผ่านเว็บ:** https://Louissrichand.github.io/srichand-orbit/

**หรือเปิดในเครื่อง:** โคลน repo แล้วดับเบิลคลิก `index.html` ได้เลย

ไม่ต้องมี Node.js, ไม่ต้องมี Docker

## ใช้ร่วมกันทั้งทีม

ล็อกอินด้วยบัญชี Microsoft 365 ของบริษัท แล้วทุกคนเห็นงานชุดเดียวกัน
ข้อมูลเก็บอยู่ใน SharePoint ของบริษัทเท่านั้น ไม่ผ่านเซิร์ฟเวอร์อื่น และไม่มีค่าบริการรายเดือน

ตั้งค่าครั้งเดียวประมาณ 15 นาที → **[SETUP-M365.md](SETUP-M365.md)**

ถ้ายังไม่ตั้งค่า Orbit ทำงานแบบเครื่องเดียวเหมือนเดิมทุกอย่าง

> **ข้อมูลตัวอย่างในระบบเป็นเรื่องสมมติทั้งหมด** ไม่ใช่ข้อมูลจริงขององค์กรใด
> ล้างทิ้งได้ที่ **ตั้งค่า → ล้างและเริ่มใหม่**

## 👥 สำหรับทีมที่มาลองใช้

**ถ้าเห็นหน้าให้ล็อกอิน** — เข้าด้วยบัญชีบริษัทได้เลย ทุกคนจะเห็นงานชุดเดียวกัน

**ถ้าเข้ามาแล้วใช้ได้ทันที** — แปลว่ายังไม่ได้เปิดโหมดทีม ข้อมูลของแต่ละคนแยกกัน
รอบนี้คือให้ลองใช้เพื่อ**ประเมินว่าเครื่องมือนี้ใช่ไหม**

ช่วยดูสามข้อนี้แล้วบอกกลับ:
1. **ขาดอะไร** ที่คุณใช้ใน Asana แล้วที่นี่ไม่มี
2. **อะไรใช้แล้วขัดใจ** — ลำดับการกดที่ไม่เข้ามือ
3. **จะใช้จริงไหม**


## สิ่งที่ทำได้

### หน้าแรก
หน้าที่เปิดขึ้นมาเจอเป็นอย่างแรก สรุปว่าวันนี้ต้องดูอะไร — งานของฉัน โปรเจกต์ที่เข้าถึงได้
งานที่เรามอบหมายให้คนอื่น และกิจกรรมล่าสุด ทุกอย่างบนหน้านี้กรองตามสิทธิ์แล้ว

### มุมมอง
| มุมมอง | ใช้ทำอะไร |
|---|---|
| รายการ | จัดกลุ่ม ลากสลับลำดับ เพิ่มงานรัว ๆ ได้ |
| บอร์ด | Kanban ลากข้ามคอลัมน์ |
| **ไทม์ไลน์** | แผนภูมิแกนต์ พร้อมเส้นโยงลำดับก่อนหลังและเส้นวันนี้ |
| ปฏิทิน | ดูตามกำหนดส่ง รายโปรเจกต์หรือรวมทุกโปรเจกต์ |
| **สรุปผล** | ตัวเลขรวม ความคืบหน้า แยกตามคน/ความสำคัญ/คอลัมน์ |

### Gantt
แถบเครื่องมือแยกสองฝั่งแบบเดียวกับ Asana ซ้ายเลื่อนดูช่วงเวลา ขวาปรับมุมมอง

- ซูม 6 ระดับ วัน สัปดาห์ เดือน ไตรมาส ครึ่งปี ปี
- **ระบายสีแท่งงาน** ตามสีโปรเจกต์ ความสำคัญ ผู้รับผิดชอบ ชนิดงาน สถานะอนุมัติ หรือความคืบหน้า พร้อมคำอธิบายสี
- **เส้นฐาน (baseline)** — เก็บวันที่ของทุกงานไว้เป็นแผนเดิม แล้วเทียบว่าตอนนี้หลุดไปกี่วัน
- **เลื่อนงานที่รออยู่ให้อัตโนมัติ** — ขยับงานหนึ่ง งานที่รอต่อจะถูกดันตามให้ลำดับยังถูกต้อง คงระยะห่างที่ตั้งใจเว้นไว้ และไม่แตะงานที่ทำเสร็จแล้ว
- คอลัมน์ฝั่งซ้ายเปิดปิดได้ กำหนดส่ง ระยะเวลา รออะไรอยู่ บล็อกงานอะไร
- กางงานย่อยเข้ามาในผังได้ ค้นหาเพื่อเน้นแถว และบันทึกทั้งชุดเป็นมุมมองพร้อมไอคอน

### บัญชีและการตั้งค่าของฉัน
กดที่ชื่อตัวเองมุมซ้ายล่าง เปิดเมนูบัญชี ตั้งสถานะไม่อยู่ แก้โปรไฟล์ และเข้าหน้าตั้งค่า

- **โปรไฟล์** ชื่อที่แสดง ตำแหน่งงาน ฝ่าย เกี่ยวกับฉัน และสีประจำตัว
- **การแจ้งเตือน** เลือกได้เป็นรายชนิดว่าเรื่องไหนควรขึ้นในกล่องข้อความ
- **การแสดงผล** ธีม ภาษา วันแรกของสัปดาห์ โหมดแน่น เลขบรรทัด — เป็นค่าของแต่ละคน ไม่ใช่ของทั้งทีม
- **ทั่วไป** หน้าที่เปิดเมื่อเข้าแอป เปิดปิดคีย์ลัด ถามยืนยันก่อนลบ
- **สถานะไม่อยู่** มีวันสิ้นสุดเสมอและหมดอายุเอง ชื่อจะมีจุดส้มกำกับให้คนที่กำลังจะมอบงานเห็นก่อน

### งาน
- ชนิดงาน: งานทั่วไป / **หมุดหมาย** / **ขออนุมัติ** (อนุมัติ – ขอแก้ไข – ไม่อนุมัติ)
- **ลำดับก่อนหลัง** — งานที่ถูกบล็อกจะขึ้นป้ายเตือน และแจ้งผู้รับผิดชอบอัตโนมัติเมื่อพร้อมทำต่อ (กันการรอวนกันให้ด้วย)
- **งานทำซ้ำ** รายวัน/สัปดาห์/เดือน — พอกดเสร็จ รอบถัดไปจะถูกสร้างให้เอง
- วันเริ่ม + กำหนดส่ง + เวลา
- งานย่อยไม่จำกัดชั้น, ความสำคัญ 5 ระดับ, แท็ก
- **ไฟล์แนบ** (ชื่อ + ลิงก์ SharePoint/OneDrive/Drive)
- **ผู้ติดตาม** และ **@mention** ในความเห็น
- ถูกใจ (♥), คัดลอกงาน, **บันทึกเป็นเทมเพลต**
- **งานชิ้นเดียวอยู่ได้หลายโปรเจกต์** — จุดเด่นของ Asana ที่ Plane และ OpenProject ไม่มี

### จัดการและติดตาม
- **กล่องข้อความ** — แจ้งเตือนจากงานที่ติดตาม พร้อมตัวนับที่ยังไม่อ่าน เก็บเข้าคลังได้
- **ตัวกรอง / เรียง / จัดกลุ่ม** และ **บันทึกมุมมอง** ไว้กดซ้ำ
- **เลือกหลายงาน** แล้วแก้พร้อมกัน (เสร็จ, มอบหมาย, ความสำคัญ, กำหนดส่ง, ลบ)
- **กฎอัตโนมัติ** — ลากเข้าคอลัมน์ไหนแล้วให้ทำอะไรต่อ
- ฟิลด์กำหนดเอง: ข้อความ / ตัวเลข / ตัวเลือก / วันที่ / บุคคล
- **สถานะโปรเจกต์** 6 แบบ ตามแผน เสี่ยง หลุดแผน พักไว้ก่อน เสร็จสมบูรณ์ ยกเลิกแล้ว — ตั้งได้จากป้ายข้างชื่อโปรเจกต์ พร้อมเก็บรายงานย้อนหลัง
- คัดลอกโปรเจกต์เป็นเทมเพลต, เก็บเข้าคลัง
- **ย้อนกลับ** ได้ 25 ขั้น
- **ลิงก์ตรงถึงงาน** — คัดลอกลิงก์ส่งให้เพื่อนร่วมทีมเปิดได้ตรงจุด
- **หน้าผู้ดูแลระบบ** — เพิ่ม/เอาสมาชิกออก ตั้งสิทธิ์ 4 ระดับ ดูที่เก็บข้อมูล และบันทึกกิจกรรมย้อนหลัง
- โหมดสว่าง / มืด / ตามระบบ
- สำรองและกู้คืนข้อมูล (ดาวน์โหลดไฟล์ หรือคัดลอก/วาง JSON)

## ⚠️ เรื่องข้อมูล ต้องอ่าน

Orbit ทำงานได้สองโหมด แยกกันชัดเจน

### โหมดทีม (ล็อกอินด้วยบัญชีบริษัท)

ทุกคนเห็นข้อมูลชุดเดียวกัน เก็บเป็นไฟล์ JSON ไฟล์เดียวบน **SharePoint ของบริษัท**
ข้อมูลไม่ออกนอก Microsoft 365 ของเรา ไม่มีเซิร์ฟเวอร์ตัวกลาง ไม่มีค่าบริการรายเดือน

- แก้แล้วเห็นทันที ระบบส่งขึ้นให้เองหลังหยุดพิมพ์ ~1.5 วินาที
- ดึงงานใหม่จากเพื่อนร่วมทีมทุก 15 วินาที
- เน็ตหลุดยังทำงานต่อได้ กลับมาแล้วส่งเอง
- ถ้าสองคนแก้พร้อมกันจริง ๆ ระบบจะ**หยุดถาม** ไม่ทับงานใครเงียบ ๆ

วิธีเปิดใช้ ดู **[SETUP-M365.md](SETUP-M365.md)** — ต้องให้ผู้ดูแลระบบตั้งค่าครั้งเดียว

### โหมดเครื่องเดียว (ยังไม่ได้ตั้งค่า หรือเลือกเอง)

ข้อมูลเก็บใน **localStorage ของเบราว์เซอร์เครื่องที่เปิด** เท่านั้น

- แต่ละเครื่องเห็นข้อมูลของตัวเอง ไม่ sync กัน
- ถ้าล้าง browsing data ข้อมูลจะหายทั้งหมด
- กด **ตั้งค่า → ดาวน์โหลดสำรอง** เก็บไฟล์ JSON ไว้สม่ำเสมอ

ถ้าเบราว์เซอร์ไม่ยอมให้เก็บข้อมูล (โหมดส่วนตัว หรือหน้าที่ถูก sandbox) ระบบจะถอยไปเก็บในหน่วยความจำแทน ใช้งานได้ครบทุกอย่างแต่ข้อมูลหายเมื่อรีเฟรช และจะมีข้อความเตือนขึ้นให้เห็น

การสลับผู้ใช้ในเมนูล่างซ้ายมีไว้ทดสอบมุมมองของแต่ละคนในโหมดเครื่องเดียว พอเข้าโหมดทีมแล้วจะกลายเป็นเมนูบัญชีจริง

```
app/main.js           ชั้นโต้ตอบ — routing, event, drag & drop, คีย์ลัด, modal

```

### สามจุดที่ตั้งใจออกแบบไว้

**1. ย้ายขึ้น server ได้โดยไม่แตะ UI**
`store.js` ซ่อนการบันทึกไว้หลัง `hydrate()` กับ `persist()` แค่ 2 ฟังก์ชัน เวลาต่อ Supabase ให้แก้แค่สองตัวนั้น `render.js` และ `main.js` ไม่ต้องแตะเลย

**2. `memberships` คือหัวใจ**
เป็นตารางกลางระหว่าง task กับ project ทำให้งานชิ้นเดียวอยู่ได้หลายโปรเจกต์ และ `position` เป็นเลขทศนิยม (fractional index) — ลากแทรกระหว่างตำแหน่ง 2 กับ 3 ได้ 2.5 อัปเดตแถวเดียวจบ ไม่ต้องเรียงใหม่ทั้งคอลัมน์ เรื่องนี้จะสำคัญมากตอนหลายคนลากพร้อมกันบน server จริง

**3. `stories` รวมความเห็นกับบันทึกกิจกรรม**
ตารางเดียว ได้ timeline ต่อเนื่องและ audit trail ฟรี

### ธีม

สีทุกค่าเป็น CSS variable ที่ `:root` คอมโพเนนต์ไม่เคยอ้างสีตรง ๆ ดาร์กโหมดนิยาม token ซ้ำ 2 ที่ — `@media (prefers-color-scheme: dark)` สำหรับตามระบบ และ `[data-theme="dark"]` สำหรับผู้ใช้เลือกเอง

## ยังไม่มี (ตั้งใจข้าม)

Portfolio, Goals/OKR, Workload, Capacity planning, Timesheet, Forms สาธารณะ, Admin console — ทีม 5–20 คนยังไม่ต้องใช้ ถ้าถึงจุดที่ต้องใช้ค่อยเติม

## ขั้นต่อไป

โหมดทีมพร้อมใช้แล้ว (ข้อ 4 กับ 5 ของแผนเดิมเสร็จไปแล้ว) ที่เหลือคือของที่จะทำเมื่อทีมโตเกินไฟล์เดียว

1. ถ้าเกิน ~20 คน หรือเจอ “ข้อมูลชนกัน” บ่อย → ย้ายไปฐานข้อมูลจริง (Supabase)
2. เขียน `hydrate()` / `persist()` ใน `store.js` ใหม่ให้เรียก Supabase client
3. เปิด Row Level Security คุมสิทธิ์ที่ชั้นฐานข้อมูล
4. แจ้งเตือนเข้า Teams เมื่อถูกมอบหมายงาน (Graph มี API ให้แล้ว)

โครงสร้างตอนนี้รองรับข้อ 1–2 อยู่แล้ว เพราะการบันทึกถูกซ่อนไว้หลังสองฟังก์ชันนั้น
