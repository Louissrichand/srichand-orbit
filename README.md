# Orbit

ระบบจัดการงานแบบ Asana สำหรับใช้เองในทีม — HTML/CSS/JavaScript ล้วน ไม่มี build step ไม่มี dependency

## ลองใช้

**เปิดผ่านเว็บ:** https://Louissrichand.github.io/srichand-orbit/

**หรือเปิดในเครื่อง:** โคลน repo แล้วดับเบิลคลิก `index.html` ได้เลย

ไม่ต้องมี Node.js, ไม่ต้องมี Docker, ไม่ต้องต่อเน็ต

> **ข้อมูลตัวอย่างในระบบเป็นเรื่องสมมติทั้งหมด** ไม่ใช่ข้อมูลจริงขององค์กรใด
> ล้างทิ้งได้ที่ **ตั้งค่า → ล้างและเริ่มใหม่**

## 👥 สำหรับทีมที่มาลองใช้

**ข้อมูลของแต่ละคนแยกกัน** — เก็บอยู่ในเบราว์เซอร์ของตัวเองเท่านั้น ยังไม่ sync กัน
รอบนี้คือให้ลองใช้เพื่อ**ประเมินว่าเครื่องมือนี้ใช่ไหม** ไม่ใช่ทำงานร่วมกันจริง

ช่วยดูสามข้อนี้แล้วบอกกลับ:
1. **ขาดอะไร** ที่คุณใช้ใน Asana แล้วที่นี่ไม่มี
2. **อะไรใช้แล้วขัดใจ** — ลำดับการกดที่ไม่เข้ามือ
3. **จะใช้จริงไหม** ถ้าทำให้ทีมเห็นข้อมูลร่วมกันได้แล้ว

### งาน
- ชนิดงาน: งานทั่วไป / **หมุดหมาย** / **ขออนุมัติ** (อนุมัติ – ขอแก้ไข – ไม่อนุมัติ)
- **ลำดับก่อนหลัง** — งานที่ถูกบล็อกจะขึ้นป้ายเตือน และแจ้งผู้รับผิดชอบอัตโนมัติเมื่อพร้อมทำต่อ (กันการรอวนกันให้ด้วย)
- **งานทำซ้ำ** รายวัน/สัปดาห์/เดือน — พอกดเสร็จ รอบถัดไปจะถูกสร้างให้เอง
- วันเริ่ม + กำหนดส่ง + เวลา
- งานย่อยไม่จำกัดชั้น, ความสำคัญ 5 ระดับ, แท็ก
- **ไฟล์แนบ** (ชื่อ + ลิงก์ SharePoint/OneDrive/Drive)
- **ผู้ติดตาม** และ **@mention** ในความเห็น
- ถูกใจ (♥), คัดลอกงาน, **บันทึกเป็นเทมเพลต**
- **งานชิ้นเดียวอยู่ได้หลายโปรเจกต์** — จุดเด่นของ Asana ที่ Plane และ OpenProject ไม่มี

### จัดการและติดตาม
- **กล่องข้อความ** — แจ้งเตือนจากงานที่ติดตาม พร้อมตัวนับที่ยังไม่อ่าน เก็บเข้าคลังได้
- **ตัวกรอง / เรียง / จัดกลุ่ม** และ **บันทึกมุมมอง** ไว้กดซ้ำ
- **เลือกหลายงาน** แล้วแก้พร้อมกัน (เสร็จ, มอบหมาย, ความสำคัญ, กำหนดส่ง, ลบ)
- **กฎอัตโนมัติ** — ลากเข้าคอลัมน์ไหนแล้วให้ทำอะไรต่อ
- ฟิลด์กำหนดเอง: ข้อความ / ตัวเลข / ตัวเลือก / วันที่ / บุคคล
- อัปเดตสถานะโปรเจกต์ (ตามแผน / เสี่ยง / หลุดแผน)
- คัดลอกโปรเจกต์เป็นเทมเพลต, เก็บเข้าคลัง
- **ย้อนกลับ** ได้ 25 ขั้น
- **ลิงก์ตรงถึงงาน** — คัดลอกลิงก์ส่งให้เพื่อนร่วมทีมเปิดได้ตรงจุด
- โหมดสว่าง / มืด / ตามระบบ
- สำรองและกู้คืนข้อมูล (ดาวน์โหลดไฟล์ หรือคัดลอก/วาง JSON)

## ⚠️ เรื่องข้อมูล ต้องอ่าน

ข้อมูลเก็บอยู่ใน **localStorage ของเบราว์เซอร์เครื่องที่เปิด** เท่านั้น แปลว่า:

- **ยังไม่ใช่ระบบหลายคน** — แต่ละเครื่องเห็นข้อมูลของตัวเอง ไม่ sync กัน
- ถ้าล้าง browsing data ข้อมูลจะหายทั้งหมด
- กด **ตั้งค่า → ดาวน์โหลดสำรอง** เก็บไฟล์ JSON ไว้สม่ำเสมอ

ถ้าเบราว์เซอร์ไม่ยอมให้เก็บข้อมูล (บางหน้าเว็บที่ sandbox หรือโหมดส่วนตัว) ระบบจะถอยไปเก็บในหน่วยความจำแทน ใช้งานได้ครบทุกอย่างแต่ข้อมูลหายเมื่อรีเฟรช และจะมีข้อความเตือนขึ้นให้เห็น

การสลับผู้ใช้ในเมนูล่างซ้ายมีไว้ทดสอบมุมมองของแต่ละคน ไม่ใช่ระบบล็อกอินจริง

## โครงสร้างโค้ด

```
index.html            โครงหน้าเว็บ
assets/styles.css     ระบบดีไซน์ + ธีมสว่าง/มืด
app/store.js          ชั้นข้อมูล — model, CRUD, กฎ, รายงาน, undo
app/render.js         ชั้นแสดงผล — คืน HTML ล้วน ไม่ผูก event
app/main.js           ชั้นโต้ตอบ — routing, event, drag & drop, คีย์ลัด, modal
build-standalone.ps1  รวมทุกอย่างเป็น Orbit-standalone.html
build-artifact.ps1    สร้างไฟล์สำหรับ publish เป็นหน้าเว็บ
```

### สามจุดที่ตั้งใจออกแบบไว้

**1. ย้ายขึ้น server ได้โดยไม่แตะ UI**
`store.js` ซ่อนการบันทึกไว้หลัง `hydrate()` กับ `persist()` แค่ 2 ฟังก์ชัน เวลาต่อ Supabase ให้แก้แค่สองตัวนั้น `render.js` และ `main.js` ไม่ต้องแตะเลย

**2. `memberships` คือหัวใจ**
เป็นตารางกลางระหว่าง task กับ project ทำให้งานชิ้นเดียวอยู่ได้หลายโปรเจกต์ และ `position` เป็นเลขทศนิยม (fractional index) — ลากแทรกระหว่างตำแหน่ง 2 กับ 3 ได้ 2.5 อัปเดตแถวเดียวจบ ไม่ต้องเรียงใหม่ทั้งคอลัมน์ เรื่องนี้จะสำคัญมากตอนหลายคนลากพร้อมกันบน server จริง

**3. `stories` รวมความเห็นกับบันทึกกิจกรรม**
ตารางเดียว ได้ timeline ต่อเนื่องและ audit trail ฟรี

### ธีม

สีทุกค่าเป็น CSS variable ที่ `:root` คอมโพเนนต์ไม่เคยอ้างสีตรง ๆ ดาร์กโหมดนิยาม token ซ้ำ 2 ที่ — `@media (prefers-color-scheme: dark)` สำหรับตามระบบ และ `[data-theme="dark"]` สำหรับผู้ใช้เลือกเอง

## ยังไม่มี (ตั้งใจข้าม)

Portfolio, Goals/OKR, Workload, Capacity planning, Timesheet, Forms สาธารณะ, Admin console — ทีม 5–20 คนยังไม่ต้องใช้ ถ้าถึงจุดที่ต้องใช้ค่อยเติม

## ขั้นต่อไป (ถ้าจะให้ทีมใช้พร้อมกันจริง)

1. สมัคร Supabase (ฟรี) สร้างตารางตาม schema ใน `store.js`
2. เขียน `hydrate()` / `persist()` ใหม่ให้เรียก Supabase client
3. เปิด Row Level Security คุมสิทธิ์ที่ชั้นฐานข้อมูล
4. ต่อ Microsoft Entra ID สำหรับล็อกอินด้วยบัญชี M365
5. อัปโหลดขึ้น Cloudflare Pages

ข้อ 1–3 คือส่วนที่ทำให้เป็นระบบหลายคนได้จริง ประเมินราว 1–2 สัปดาห์
